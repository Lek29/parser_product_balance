# Парсер остатков — Telegram-бот

Telegram-бот для мониторинга товарных остатков. Получает Excel-таблицу с остатками из корпоративной почты (Яндекс IMAP), парсит иерархию товаров и позволяет выгружать позиции с малым запасом прямо в чат.

---

## Возможности

- Авторизация по паролю с защитой от брутфорса (блокировка после 5 неверных попыток)
- Ручная проверка почты и обновление остатков через кнопку в боте
- Автоматическое обновление по расписанию — каждый понедельник в 09:00 МСК
- Выгрузка отфильтрованного `.xlsx` с позициями, у которых остаток ≤ порога
- Поддержка вложений в форматах `.zip` и `.rar`
- Меню команд Telegram (`☰ Menu`): `/start`, `/help`

### Источники данных

| Файл | Роль |
|------|------|
| `storage/current.xlsx` | Актуальная таблица остатков с почты; основной вход для парсинга и кнопок бота. |
| `storage/meta.json` | Дата/метаданные последнего письма и загрузки; статус «актуально на …» в боте. |
| `storage/data.json` | **Производный** кэш полного списка позиций после парсинга (не источник истины в рантайме). |
| `storage/filtered.xlsx` | Глобальная выгрузка «малый остаток» после пайплайна. |

Пайплайн после успешной загрузки с почты: парсинг xlsx → запись `data.json` → фильтр → `filtered.xlsx` (порядок фиксирован в `services/stock_pipeline.py`).

## Переменные окружения

Создайте файл `.env` в корне проекта:

```env
# Telegram
TELEGRAM_BOT_TOKEN=your_bot_token_here
BOT_PASSWORD=your_secret_password

# Почта (Яндекс или другой IMAP-сервер)
EMAIL_ADDRESS=example@yandex.ru
EMAIL_PASSWORD=your_email_password
EMAIL_IMAP_SERVER=imap.yandex.ru

# Порог остатка (позиции с количеством <= этого значения попадают в выгрузку)
STOCK_THRESHOLD=5
```

| Переменная | Обязательная | Описание |
|------------|:---:|---------|
| `TELEGRAM_BOT_TOKEN` | ✅ | Токен от [@BotFather](https://t.me/BotFather) |
| `BOT_PASSWORD` | ✅ | Пароль для входа в бота |
| `EMAIL_ADDRESS` | ✅ | Адрес почты для получения остатков |
| `EMAIL_PASSWORD` | ✅ | Пароль от почты |
| `EMAIL_IMAP_SERVER` | ✅ | IMAP-сервер (например `imap.yandex.ru`) |
| `STOCK_THRESHOLD` | ❌ | Порог малого остатка, по умолчанию `5` |

## Запуск

### Локально

```bash
# Создать виртуальное окружение
python -m venv .venv
.venv\Scripts\activate        # Windows
# source .venv/bin/activate   # Linux/macOS

# Установить зависимости
pip install -r requirements.txt

# Запустить
python main.py
```

Минимальные тесты (без сети и Telegram):

```bash
pytest tests/
```

Разовая проверка загрузки с почты без бота: `python scripts/dev_fetch_mail.py` (нужен валидный `.env`).  
Просмотр `meta.json`: `python scripts/show_meta.py`.

> На Linux для поддержки `.rar` установите `unrar`:
> ```bash
> sudo apt-get install unrar-free
> ```

### Docker

Файл: `docker-compose.yaml` (совместим с `docker compose` v2).

```bash
docker compose up -d --build
```

Часовой пояс контейнера: `Europe/Moscow` (совпадает с планировщиком APScheduler).  
Данные из `storage/` и `temp/` монтируются как volumes — сохраняются между перезапусками.  
Сборка использует `.dockerignore` (в образ не попадают тесты, `.git`, `.env` и т.д.).

## Логика парсинга Excel

Таблица остатков имеет иерархическую структуру, определяемую по отступу (`indent`) ячеек:

| Отступ | Уровень |
|--------|---------|
| 4 | Категория (Аксессуары, Мячи…) |
| 6 | Подкатегория (Гетры, Очки…) |
| 8 | Бренд (Atemi, Speedo…) |
| 10 | Товарная группа / SKU |
| 12 | Конкретный вариант (цвет, размер) |

Реальными товарными позициями считаются только строки с отступом **10** и **12**.

## Автоматическое расписание

Планировщик запускается в фоновом потоке вместе с ботом.  
Задача выполняется **каждый понедельник в 09:00 по Москве**.  
Допустимое опоздание (misfire grace time) — 1 час.

Цикл задачи:
1. Подключиться к IMAP, найти последнее письмо с архивом
2. Сравнить дату письма с `meta.json` — если уже актуально, пропустить
3. Скачать и распаковать архив → `storage/current.xlsx`
4. Распарсить таблицу → `storage/data.json` (кэш полного списка)
5. Сгенерировать выгрузку → `storage/filtered.xlsx`

При очень большом числе товарных групп reply-клавиатура «частичной фильтрации» может стать громоздкой; возможная пагинация групп — отдельная доработка (см. `docs/refactoring-plan2.md`).
